# MCP Server Setup - Claude Desktop / opencode Integration

## Обзор

MCP (Model Context Protocol) сервер позволяет Claude Desktop и opencode использовать Avito Scraper напрямую через встроенные инструменты.

Первый поисковый запрос или запрос карточки открывает видимое окно Chromium. MCP переиспользует вкладку, а профиль хранится на диске в `~/.avito-scraper/mcp-profile`. При необходимости задайте отдельный абсолютный путь через `AVITO_PROFILE_DIR`. Для одновременной работы нескольких MCP-клиентов укажите отдельный каталог каждому клиенту.

## Установка

### 1. Собрать проект

```bash
cd C:\Temp\mcp-avito
pnpm install
pnpm exec playwright install chromium
pnpm build
```

### 2. Найти конфигурационный файл Claude Desktop

**Windows:**
```
%APPDATA%\Claude\claude_desktop_config.json
```

Полный путь обычно:
```
C:\Users\<USERNAME>\AppData\Roaming\Claude\claude_desktop_config.json
```

**macOS:**
```
~/Library/Application Support/Claude/claude_desktop_config.json
```

**Linux:**
```
~/.config/Claude/claude_desktop_config.json
```

### 3. Добавить конфигурацию MCP сервера

Откройте файл `claude_desktop_config.json` и добавьте:

```json
{
  "mcpServers": {
    "avito-scraper": {
      "command": "node",
      "args": [
        "C:\\Temp\\mcp-avito\\dist\\mcp\\server.js"
      ]
    }
  }
}
```

**Важно:** Замените пути на абсолютные пути к вашим файлам!

**macOS/Linux:**
```json
{
  "mcpServers": {
    "avito-scraper": {
      "command": "node",
      "args": [
        "/absolute/path/to/mcp-avito/dist/mcp/server.js"
      ]
    }
  }
}
```

### 4. Перезапустить Claude Desktop

Полностью закройте и откройте Claude Desktop заново.

## Настройка для opencode

opencode подключает MCP-сервер через проектный конфиг `opencode.json` (в корне проекта). Файл уже добавлен в репозиторий:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "avito": {
      "type": "local",
      "command": ["node", "dist/mcp/server.js"],
      "enabled": true
    }
  }
}
```

**Шаги:**

1. Убедитесь, что проект собран (нужен `dist/mcp/server.js`):
   ```bash
   pnpm install && pnpm build
   ```
2. Проверьте, что пути в `opencode.json` указывают на ваш проект (пути абсолютные).
3. Перезапустите opencode — конфиг читается только при старте, хот-релоада нет.

**Проверка:** после запуска в opencode появятся инструменты с префиксом `avito_` (`avito_search`, `avito_get_details`, `avito_search_all`).

## Доступные инструменты

После настройки в Claude Desktop появятся 3 новых инструмента:

### 1. `avito_search`

Поиск товаров на Avito.ru. Каждая карточка содержит `seller.reviewsCount` и
`seller.reviewsCountApproximate`. Например, `1,2 тыс. отзывов` возвращается как `1200`
с признаком приблизительного значения; неизвестное число — `null`, явное отсутствие отзывов — `0`.

Если пользователь задал ограничение по отзывам, MCP-клиент сравнивает точные значения
с этим ограничением **до вызова `avito_get_details`** и пропускает неподходящие карточки.
Неизвестные и приблизительные значения требуют уточнения при строгом пороге.
Сам поиск возвращает все карточки, поэтому страница без подходящих кандидатов не завершает обход.

**Параметры:**
- `query` (обязательно) - Поисковый запрос
- `price_min` (опционально) - Минимальная цена в рублях
- `price_max` (опционально) - Максимальная цена в рублях
- `location_id` (опционально) - ID региона
- `page` (опционально) - Номер страницы (по умолчанию: 1)
- `sort` (опционально) - Сортировка: default, date, price_asc, price_desc

**Пример использования в Claude Desktop:**

```
Найди Samsung SSD до 15000 рублей на Avito
```

Claude автоматически вызовет:
```json
{
  "query": "Samsung SSD",
  "price_max": 15000
}
```

### 2. `avito_get_details`

Получить детальную информацию о товаре

**Параметры:**
- `url` (обязательно) - URL товара на Avito

**Пример:**

```
Покажи детали этого объявления: https://www.avito.ru/moskva/tovary_dlya_kompyutera/...
```

### 3. `avito_search_all`

Поиск по всем страницам (множество результатов). Возвращает те же поля отзывов продавца,
что и `avito_search`; отсев по отзывам выполняется перед запросом details.

**Параметры:**
- `query` (обязательно) - Поисковый запрос
- `price_min`, `price_max`, `location_id`, `sort` - Фильтры
- `limit` (опционально) - Максимальное количество результатов

**Пример:**

```
Найди все MacBook Pro до 100000 рублей на Avito (макс 50 штук)
```

## Примеры диалогов с Claude Desktop

### Пример 1: Простой поиск

**Вы:**
```
Найди iPhone 13 на Avito до 50000 рублей
```

**Claude:**
Использует `avito_search`:
```json
{
  "query": "iPhone 13",
  "price_max": 50000
}
```

Выведет:
```
Найдено 50 объявлений:

1. iPhone 13 128GB - 45000₽
   Москва
   https://www.avito.ru/...

2. iPhone 13 Pro 256GB - 48000₽
   Санкт-Петербург
   https://www.avito.ru/...

...
```

### Пример 2: С детальной информацией

**Вы:**
```
Найди самый дешевый Samsung SSD на Avito и покажи его детали
```

**Claude:**
1. Вызывает `avito_search` с `sort: "price_asc"`
2. Берет первый результат
3. Вызывает `avito_get_details` с URL товара
4. Показывает полную информацию

### Пример 3: Сравнение цен

**Вы:**
```
Сравни цены на MacBook Pro M3 на Avito
```

**Claude:**
1. Вызывает `avito_search` с запросом "MacBook Pro M3"
2. Анализирует результаты
3. Выводит статистику: минимальная, максимальная, средняя цена
4. Показывает лучшие предложения

## Отладка

### Проверить, что MCP сервер работает

```bash
cd C:\Temp\mcp-avito
pnpm mcp:dev
```

Сервер должен вывести:
```
Avito MCP server running on stdio
```

### Проверить логи Claude Desktop

**Windows:**
```
%APPDATA%\Claude\logs\
```

**macOS:**
```
~/Library/Logs/Claude/
```

### Типичные проблемы

#### 1. "MCP server not found"

**Проблема:** Неверные пути в конфигурации

**Решение:**
- Убедитесь что пути абсолютные (не относительные)
- Проверьте что файл `dist/mcp/server.js` существует
- На Windows используйте двойные обратные слеши: `C:\\Temp\\...`

#### 2. "Browser not found"

**Проблема:** Chrome не найден

**Решение:**
- Добавьте переменную окружения `CHROME_EXECUTABLE_PATH` в конфиг
- Или установите Chromium: `npx playwright install chromium`

#### 3. Капча и ограничения доступа

- При видимой CAPTCHA сервер показывает баннер и до 120 секунд ждёт ручного решения. Это работает и на странице проверки с HTTP 403. После решения сервер подтверждает доступ к целевому URL и продолжает текущий запрос.
- `CAPTCHA_DETECTED` — время ожидания истекло или проверка осталась нерешённой. Пройдите её в открытом окне Chromium и повторите запрос. Окно и текущий прокси сохраняются.
- `AVITO_ACCESS_RESTRICTED` — Авито ограничил доступ. В открытом окне можно увидеть сообщение площадки.
- `AVITO_RATE_LIMITED` — Авито вернул HTTP 429. Повторите запрос позже.

Таймаут вызова инструмента в MCP-клиенте должен учитывать ручную проверку (120 секунд плюс загрузка страниц). Скрытые контейнеры CAPTCHA не останавливают сбор. Настройки `webdriver`, viewport, locale и timezone одинаковы с обычным режимом; используется нативный UA Chromium. При штатном завершении MCP дожидается закрытия браузера и сохранения профиля, включая постоянные cookies.

## Прокси поддержка (опционально)

Настройки можно передать в `env` конфигурации MCP-клиента или записать в `.env` в корне `mcp-avito`. Сервер читает этот файл независимо от рабочего каталога клиента. Переменные окружения процесса имеют приоритет над `.env`. После изменения настроек перезапустите MCP-сервер.

Для одного прокси:

```env
PROXY_ENABLED=true
PROXY_URL=http://user:password@proxy.example.com:8080
```

Для пула прокси:

```env
PROXY_ENABLED=true
PROXY_LIST_FILE=./config/proxies.txt
PROXY_ROTATION=round-robin
PROXY_ROTATE_ON_ERROR=true
PROXY_ROTATE_EVERY_N=10
```

Файл содержит по одному адресу на строку. Пустые строки и комментарии, начинающиеся с `#`, пропускаются:

```text
http://user:password@proxy1.example.com:8080
https://proxy2.example.com:443
socks5://user:password@proxy3.example.com:1080
socks4://proxy4.example.com:1080
```

| Переменная | Значение по умолчанию | Поведение |
| --- | --- | --- |
| `PROXY_ENABLED` | Включено, если задан URL или файл | `true` / `false`; явное `false` отключает прокси, включая настройки из `.env` |
| `PROXY_URL` | Не задана | Один прокси; имеет приоритет над `PROXY_LIST_FILE` |
| `PROXY_LIST_FILE` | Не задана | Абсолютный путь или путь относительно корня `mcp-avito` |
| `PROXY_ROTATION` | `sequential` | `sequential`, `random`, `round-robin` |
| `PROXY_ROTATE_ON_ERROR` | `true` | При ошибке навигации пометить прокси нерабочим и выбрать следующий при следующем вызове |
| `PROXY_ROTATE_EVERY_N` | `0` | Неотрицательное целое число; `0` отключает периодическую ротацию |

Указывайте схему и порт явно. В логине и пароле специальные символы нужно кодировать как в URL: `@` → `%40`, `:` → `%3A`, `/` → `%2F`, `%` → `%25`, `#` → `%23`. Для SOCKS с авторизацией сервер автоматически запускает локальный HTTP-туннель на `127.0.0.1`.

Записи с одним адресом шлюза, но разными логинами или паролями учитываются как отдельные прокси-сессии во всех трёх стратегиях. Внутренние ключи и статистика используют отпечаток учётных данных, не раскрывая логин или пароль. SOCKS4 передаёт USERID; парольная авторизация относится к HTTP/HTTPS/SOCKS5.

Счётчик ротации учитывает переходы scraper к страницам поиска и карточкам, включая страницы `avito_search_all`, повторное открытие при fallback и подтверждение доступа после CAPTCHA; загрузки изображений и других ресурсов не считаются. При смене прокси Chromium перезапускается с тем же профилем. Закрытие окна не сбрасывает прокси и не приводит к повторной загрузке списка.

Ошибка навигации возвращается текущему вызову без автоматического повтора. Ответы HTTP 403/429 и CAPTCHA обрабатываются отдельно и сами по себе не помечают прокси нерабочим. Пока открыта нерешённая CAPTCHA, сервер сохраняет окно для ручной проверки, даже если подошло время ротации.

При некорректных переменных сервер завершается с `MCP_CONFIG_ERROR`. Отсутствующий, пустой или некорректный файл прокси, а также исчерпание доступного пула возвращают `PROXY_ERROR` при обращении к инструменту. В этих случаях сервер не запускает браузер с прямым подключением. Логины и пароли не выводятся в сообщения конфигурации и прокси.

## Безопасность

⚠️ **Важно:**

- MCP открывает Chromium с выделенным профилем. Используйте для `AVITO_PROFILE_DIR` отдельный каталог.
- Профиль может содержать cookies и данные сессии. Храните его вне репозитория.

## Производительность

### Оптимизация

MCP сервер переиспользует один экземпляр браузера между запросами для ускорения:

- Первый запрос: ~3-5 секунд (запуск браузера)
- Последующие запросы: ~2-3 секунды (только навигация)

### Лимиты

- `avito_search` - возвращает до 50 результатов (ограничение Avito)
- `avito_search_all` - может вернуть сотни результатов, используйте `limit`
